# React 工作台实施计划

目标：按用户确认的 React + TypeScript + Vite + Tailwind CSS 浅色方案，迁移四个工作区并保留已有流程。

架构：React 组件负责页面结构，构建时预渲染至 FastAPI 现有模板，浏览器 hydration 后启动现有业务控制器。表单保持非受控，以兼容已验证的版本、草稿与审核逻辑。业务控制器单独保留为 JS，不伪装成已完成 TypeScript 迁移。后端 API、模型调用与验收边界不改动。

设计：白色表单、浅灰蓝画布、靛蓝操作按钮；中文系统字体；固定桌面侧栏、移动端横向导航；创作页左右分栏，海报区域突出。高级工具可折叠，清晰区分生成、检查、人工审核。

- [x] 建立可复现的 npm 工程、类型检查与预渲染构建。
- [x] 将创作、批量、审核、执行记录拆分为 React 组件，保留字段 ID 与测试接口。
- [x] 实现浅色响应式视觉体系、预览缩放、键盘与加载失败反馈。
- [x] 运行现有 Python/Node 回归与真实 Chrome 流程，检查桌面和移动端。
- [x] 更新开发说明与构建检查，启动实际工作台供查看。

重点验证：hydration 不重置草稿；控制器仅初始化一次；批量及审核状态不跨工作区丢失；预览缩放不改变导出文件；无网络或无脚本时不展示可误操作的空界面。

验证结果：634 项 Python/Node 测试通过；4 组原有 Chrome 回归通过；新增正式构建 Chrome 回归通过；类型检查、格式检查及构建通过。
开发预览同样通过新增 Chrome 全流程回归；已停止测试服务并从原项目数据目录启动 8000 端口。
