# 人工审核进度保存

方形海报、经典分栏 4:5、商品主体优先 4:5 的日常人工审核可以保存尚未填写完成的字段，不需要先执行 OCR。正式审核记录继续使用原有显式提交及追加历史机制。

## 操作流程

1. 打开海报，进入对应的方形或原生 4:5 人工审核。
2. 填写任意判断或理由，停止输入约 0.7 秒后自动保存。也可点击「保存进度」立即同步。
3. 等待「进度已保存于本机」再关闭。刷新或重新打开同一版本、版式及审核员时会恢复已保存内容。
4. 填完全部适用字段后点击「提交方形审核」或「提交 4:5 审核」，形成正式记录。草稿本身不会增加审核数量、进入 CSV 评分或改变质量结论。

新版本、不同版式、不同审核员以及图片/规格/源素材变化都不会继承另一份草稿。正式提交后会使用新的进度空间，旧草稿不会覆盖已经提交的标签。旧空间文件保留在本机，不自动删除。

## 同时编辑和网络失败

服务按每份草稿维护递增版本，保存时核对读取时的版本。如果另一页面已更新不同内容，旧页面会收到 409，服务器保留已保存进度，当前页面保留自己的输入。

「载入已保存进度」可重新载入服务器版本。如果有尚未保存的本页输入，会先提示替换影响；取消后输入保持原样。不要通过改请求版本或删除草稿文件绕过冲突。

网络失败时，本页会把输入临时备份到同源浏览器存储，按标签页和图片身份隔离。刷新同一标签页可恢复备份；重连后会自动尝试同步。若服务器也已有新修改，仍需先处理冲突，不会强行覆盖。临时备份不可用且服务器保存失败时，会明确提示进度尚未保存。页面存在未同步内容时，离开会触发浏览器提醒。

临时浏览器备份不是跨设备备份。应等到服务器显示已保存再关闭；清理浏览器数据会删除临时备份。本地已保存草稿位于 `POSTER_DATA_DIR/<poster_id>/versions/vN.<variant>.review_drafts/`，与正式审核目录分开，应随其他本地项目数据备份。

## 接口契约

`GET /api/posters/{poster_id}/versions/{version}/review-draft?variant=<variant>&reviewer=<alias>`

`PUT /api/posters/{poster_id}/versions/{version}/review-draft?variant=<variant>&reviewer=<alias>`

`variant` 为 `square`、`feed_4x5_native` 或 `feed_4x5_native_product_focus`，默认方形。审核员沿用 2–40 位英文字母、数字、下划线或短横线。

PUT 使用 JSON，最大 16 KiB；交互式请求格式可在 `/docs` 查看：

| 字段 | 约束 |
| --- | --- |
| `source_sha256` | 使用最近 GET 返回的身份摘要，绑定图片、规格、版式、审核员、原生素材及当前正式审核记录 |
| `expected_revision` | 最近 GET/PUT 返回的非负整数，初始为 0；布尔值不作为整数接受 |
| `fields` | 当前版式适用字段的子集，最多 8 项 |
| `fields.<name>.judgment` | `correct` / `defective` / `unsure` / 空字符串；允许未完成 |
| `fields.<name>.reason` | 最多 300 字，可留空 |

响应包括 `status=DRAFT`、实际 `revision`、系统保存时间 `saved_at`、字段与源身份；`automatically_accepted=false`。保存时间不代表人工完成审核的时间。相同内容在响应丢失后重试不会产生重复版本或错误覆盖。

409 表示并发版本冲突、来源变化、草稿损坏或无法安全读写；422 表示请求或字段无效；413 表示请求超限。草稿读写拒绝符号链接和非普通文件，写入复用本地临时文件、fsync 与原子替换。磁盘写入失败会保留上一次完整文件。

这是本机单 Worker 的进度保护，不是身份认证、租户隔离或分布式事务。M6 的冻结 CSV、OCR 证据和审核侧车文件保持各自的协议；此自动保存不修改冻结证据，也不代替其 JSON 导出和最终人工验收。
